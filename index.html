Da pc non parte l'audio. Questo è un classico blocco di sicurezza dei browser su PC (Chrome/Edge/Safari). Quando si usano motori AI in locale e la Web Audio API, i browser da computer applicano regole molto più rigide rispetto agli smartphone. I problemi scatenanti sono quasi sempre due: stai aprendo il file facendo doppio clic (protocollo file://) oppure il browser ha bloccato il multi-threading. Ecco i 3 passaggi per sbloccare l'audio su PC: 1. Non aprire il file con "Doppio Clic" (Errore CORS) Se hai fatto doppio clic sul file index.html (e nella barra degli indirizzi vedi file:///C:/...), il browser blocca il download del modello AI per motivi di sicurezza (CORS policy). Soluzione: Devi caricarlo su GitHub Pages (come avevamo previsto all'inizio) e aprirlo dal link pubblico (es. [https://tuonome.github.io/carpdf](https://tuonome.github.io/carpdf)), oppure se vuoi testarlo in locale sul PC devi usare un server locale (come l'estensione Live Server su VS Code). 2. Disabilita il Multi-threading forzato Nel codice precedente avevo forzato 4 processori (numThreads = 4) per far volare i chip Snapdragon. Su PC, se il server non invia delle intestazioni di sicurezza speciali (chiamate Cross-Origin-Embedder-Policy), Chrome disabilita i SharedArrayBuffer e il motore AI va in crash silenzioso. 3. Inizializza l'Audio solo al clic Su PC, se l'audio viene preparato prima che l'utente clicchi un pulsante, il browser lo "muta" permanentemente (Autoplay Policy).
